# OA auto review exposes four decisions

OA Auto Review keeps `pass`, `reject`, `manual_review`, and `exception` as distinct domain, persistence, and polling decisions. Zero confirmed differences produce `pass`; one or two confirmed differences produce `manual_review`; three or more confirmed differences produce `reject`. `reject` requires complete evidence and a deterministic business-negative rule. Incomplete or contradictory evidence becomes `manual_review` regardless of the provisional mismatch count, while database, NAS, OCR, LLM, and RPA technical failures become `exception` and must never be represented as a business rejection or automatic pass.

The deployed OA callback receiver supports only the transport decisions `pass`, `reject`, and `exception`. For an automatic result that requires human review, the callback uses transport `decision=pass` to route the request to the next human node and carries `review_decision=manual_review`, `next_node_review_required=true`, `manual_review_reasons`, and `manual_review_reason_text`. Transport `pass` is not a domain approval in this case. An explicit human request for more information remains a non-retryable `exception` with `error.code=REVIEW_REQUIRES_MANUAL_REVIEW` so OA can return the request for supplementation. Neither projection changes the persisted domain decision.
