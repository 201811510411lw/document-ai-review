# OA auto review exposes four decisions

OA Auto Review keeps `pass`, `reject`, `manual_review`, and `exception` as distinct domain, persistence, and polling decisions. Zero confirmed differences produce `pass`; one to three confirmed differences produce `manual_review`; four or more confirmed differences produce `reject`. `reject` requires complete evidence and a deterministic business-negative rule. Incomplete or contradictory evidence becomes `manual_review` regardless of the provisional mismatch count, while database, NAS, OCR, LLM, and RPA technical failures become `exception` and must never be represented as a business rejection or automatic pass.

The deployed OA callback receiver supports only the transport decisions `pass`, `reject`, and `exception`. For an automatic result that requires human review, the callback uses non-retryable transport `decision=exception` with `error.code=REVIEW_REQUIRES_MANUAL_REVIEW` to route the request to the dedicated human-review node. It also carries `review_decision=manual_review`, `next_node_review_required=true`, `manual_review_reasons`, and `manual_review_reason_text`. An explicit human request for more information uses the same non-retryable `exception`, but sets `next_node_review_required=false` so OA can return the request for supplementation. Neither projection changes the persisted domain decision.
