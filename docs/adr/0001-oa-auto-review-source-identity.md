# OA auto review is scoped by OA request identity

An OA source request is identified by `workflow_id + requestid`. The application derives each review submission from the latest applicant-submit event in `workflow_requestlog`: its stable `LOGID` is persisted as `submission_log_id`, and the event order becomes the positive `submission_version`. OA callers do not need to send a version. Repeated delivery of the same submit event reuses the same task; a new submit event after a return creates a new Review Task and reloads evidence from the exact OA request. If no submit event exists, the request is treated as the first submission; a query failure is returned as unavailable rather than replaying an old result. Version `1` retains the legacy task ID `tc-oa-{workflow_id}-{requestid}`, while later versions use `tc-oa-{workflow_id}-{requestid}-s{submission_version}`. The source adapter must never infer the request from a store name, title, or latest record. Request-provided callback URLs are not trusted source configuration; outbound result delivery uses only the server-managed callback URL.
